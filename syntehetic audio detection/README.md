## 1. What is PRISM?

**PRISM** (Probabilistic Recognition of Inauthentic Spectral Markers) is a **Tier A** lightweight audio authenticity detector.

| Property | Value |
|----------|-------|
| Approach | Zero-shot heuristics (no ML training) |
| Input | Any audio file — `.wav`, `.mp3`, `.flac`, `.ogg` |
| Output | Synthetic probability score `0.0 → 1.0` |
| Languages | Python 3.10+ |
| Dependencies | `librosa`, `numpy`, `scipy`, `pandas` |
| Hardware | CPU only — no GPU required |
| Speed | ~1–3 seconds per file |

### What it can detect

| AI System | Type | Detector Used |
|-----------|------|---------------|
| HiFi-GAN | Neural vocoder | Vocoder detector |
| WaveGlow | Neural vocoder | Vocoder detector |
| WaveNet | Neural vocoder | Vocoder detector |
| Tacotron 2 | TTS | Vocoder detector |
| MelGAN | GAN synthesiser | GAN detector |
| EnCodec | GAN codec | GAN detector |
| AudioLDM | Diffusion model | Diffusion detector |
| Stable Audio | Diffusion model | Diffusion detector |
| Suno / Udio | Diffusion/GAN | GAN + Diffusion detectors |

## 2. How Does It Work?

### The core idea

Every AI audio generator leaves **physical fingerprints** in the sound wave — tiny mathematical patterns that are invisible to the human ear but measurable by signal processing. PRISM looks for exactly these patterns.

Think of it like a forensic document examiner: a skilled expert can spot a forged signature without ever having seen that specific forgery before, because forgeries share tell-tale physical properties (pen pressure inconsistencies, stroke order anomalies). PRISM does the same thing for audio.

### Why AI audio sounds different (physically)

```
Real human voice:
  ┌─────────────────────────────────────────┐
  │ Formants jump around naturally          │ ← irregular, organic
  │ Background noise varies with the room  │ ← dynamic, non-uniform
  │ Energy envelope is highly variable     │ ← loud/soft/loud/soft
  │ Phase is coherent across harmonics     │ ← physically consistent
  └─────────────────────────────────────────┘

AI-generated voice (HiFi-GAN):
  ┌─────────────────────────────────────────┐
  │ Formants are too smooth / frozen       │ ← mathematical artefact
  │ Background noise is perfectly flat     │ ← no room acoustics
  │ Energy envelope is eerily steady       │ ← over-regularised
  │ Phase has discontinuities at 8kHz+    │ ← upsampler artefact
  └─────────────────────────────────────────┘
```

### Stage 1 — Preprocessor (`preprocessor.py`)

Converts the raw audio file into mathematical representations used by all detectors.

```
Input:  any audio file path
Output: dict containing →

  audio       → raw waveform as numbers [-1.0 to +1.0]  (shape: N samples)
  sr          → sample rate = 22,050 Hz
  stft_full   → Short-Time Fourier Transform (complex numbers, shape: F×T)
  stft_mag    → magnitude of STFT  (how loud each frequency is)
  stft_phase  → phase of STFT      (the "timing" of each frequency)
  mel_spec    → mel-spectrogram in dB (human-ear-weighted frequency view)
```

**Key parameters:**

| Parameter | Value | Why |
|-----------|-------|-----|
| Sample rate | 22,050 Hz | Standard for speech/music ML |
| Max duration | 30 seconds | Covers all artifact patterns |
| FFT window | 2,048 samples | ~93ms resolution, good freq detail |
| Hop length | 512 samples | ~23ms between frames |
| Mel bands | 128 | High resolution, matches human hearing |
| Freq range | 20–8,000 Hz | Covers all speech + music fundamentals |

---

### Stage 2 — Domain Classifier (`domain.py`)

Determines whether the audio is **speech**, **music**, or **environmental** sound.  
This matters because different AI generators target different domains, so the weights applied in Stage 4 differ.

**Features computed:**

| Feature | What it measures |
|---------|-----------------|
| Zero-Crossing Rate (ZCR) | How often the waveform crosses zero — high for speech |
| Spectral Centroid | The "centre of mass" of the frequency spectrum |
| Spectral Rolloff | Frequency below which 85% of energy lies |
| MFCC variance | How much the tonal colour varies over time |

**Decision rules (first match wins):**

```
IF   ZCR_mean > 0.15
AND  spectral_centroid < 3,000 Hz        →  "speech"

ELSE IF  spectral_rolloff > 6,000 Hz
AND      MFCC[1] variance > 50           →  "music"

ELSE                                     →  "environmental"
```

---

### Stage 3 — Artifact Detectors (`detectors.py`)

Three independent detectors run in parallel, each targeting a different family of AI generators.

---

#### Detector A — Vocoder Score
**Targets:** HiFi-GAN, WaveGlow, WaveNet, Tacotron 2

**Feature 1 — Spectral Banding Index:**

Neural vocoders upsample from a compressed mel-spectrogram back to audio.  
This leaves a "staircase" pattern — some mel bands are unnaturally uniform while adjacent bands differ sharply.

```
Real speech mel-bands:      Vocoder mel-bands:
  Band 10: -23.4 dB           Band 10: -20.0 dB
  Band 11: -24.1 dB           Band 11: -20.0 dB  ← suspiciously flat
  Band 12: -19.8 dB           Band 12: -20.1 dB
  Band 13: -31.2 dB           Band 13: -27.0 dB  ← sudden jump
  Band 14: -30.9 dB           Band 14: -27.0 dB  ← flat again

  variance of diffs ≈ 2.1       variance of diffs ≈ 12.7  ← HIGH = artifact
```

Score = `min(1.0, variance / 3.0)`

**Feature 2 — Formant Smoothness (speech only):**

Formants are resonant frequencies of the vocal tract (F1, F2, F3).  
Real speech has naturally jumpy formants as the mouth/tongue moves.  
Vocoders predict formants from a neural network — making them unnaturally smooth.

```python
# Per 25ms frame: extract LPC coefficients → find poles → get formant frequencies
lpc_coeffs = librosa.lpc(frame, order=12)
roots       = np.roots(lpc_coeffs)             # complex poles
frequencies = angle(roots) * sr / (2π)        # Hz

# Measure frame-to-frame change
delta_std_real   ≈ 60–120 Hz    (mouth moves quickly)
delta_std_vocoder ≈ 5–15 Hz    (too smooth → suspicious)

Score = max(0,  (40 - delta_std) / 40)
```

**Aggregation:**
```
Speech domain:   score = 0.4 × banding + 0.6 × formant_smoothness
Other domains:   score = 1.0 × banding
```

---

#### Detector B — GAN Score
**Targets:** MelGAN, EnCodec, GAN-based music generators

**Feature 1 — High-Frequency Checkerboard:**

GAN generators that upsample audio in frequency domain create a "checkerboard" aliasing pattern above 8 kHz — energy that pulses in a regular beat every 1–4 frames.

```
Real audio HF energy:    0.12  0.09  0.15  0.08  0.11  0.13  (random)
GAN HF energy:           0.10  0.20  0.10  0.20  0.10  0.20  (regular pulses!)

Autocorrelation at lag-2 ≈ 0.95  ← very high = artifact
```

Score = `max normalised peak in autocorrelation[lags 1–4]`

**Feature 2 — Phase Incoherence:**

Real audio has harmonically structured phase — each frequency's phase is predictable from its neighbours.  
GAN optimisers only minimise mel-loss (how the spectrogram *looks*) — they ignore phase, leaving random discontinuities.

```
Instantaneous Frequency = d/dt (unwrapped_phase)
Expected IF             = linear ramp across frequency bins
Deviation               = std(actual_IF - expected_IF) per frame

Real audio deviation    ≈ 0.2–0.4 rad/s
GAN audio deviation     ≈ 0.9–2.5 rad/s   (phase chaos)

Score = min(1.0, deviation / 0.8)
```

**Aggregation:**
```
score = 0.5 × checkerboard + 0.5 × phase_incoherence
```

---

#### Detector C — Diffusion Score
**Targets:** AudioLDM, Stable Audio, Suno, Udio

**Feature 1 — Flat Noise Floor:**

Real recordings have dynamic background noise — it gets louder, quieter, shifts with room acoustics.  
Diffusion models generate a perfectly consistent "synthetic silence" that never varies.

```
Real recording noise floor:      -48, -52, -41, -60, -38, -55 dB  (variance = 51.2)
Diffusion model noise floor:     -50, -50, -49, -50, -50, -50 dB  (variance = 0.2) ← flat

Score = max(0,  1 - variance / 0.5)
```

**Feature 2 — Energy Consistency:**

Real audio has highly variable loudness (CoV > 0.4).  
Diffusion models tend to produce eerily uniform output energy (CoV < 0.2).

```
CoV = standard_deviation(RMS per 100ms window) / mean(RMS)

Real speech CoV:       0.45 → 0.90  (loud-soft-loud naturally)
Diffusion audio CoV:   0.05 → 0.15  (unnaturally constant)

Score = max(0,  (0.4 - CoV) / 0.4)
```

**Aggregation:**
```
score = 0.5 × flat_noise + 0.5 × energy_consistency
```

---

### Stage 4 — Domain-Weighted Aggregator (`aggregator.py`)

Different AI generators dominate in different domains, so the final score uses domain-specific weights:

| Domain | Vocoder weight | GAN weight | Diffusion weight | Reasoning |
|--------|---------------|------------|-----------------|-----------|
| Speech | **0.55** | 0.25 | 0.20 | Most speech AI = vocoders (HiFi-GAN, WaveNet) |
| Music | 0.20 | **0.50** | 0.30 | Most music AI = GAN-based (MelGAN, EnCodec) |
| Environmental | 0.15 | 0.30 | **0.55** | Most env AI = diffusion (AudioLDM, Stable Audio) |

```python
final_score = (w_vocoder × vocoder_score)
            + (w_gan     × gan_score)
            + (w_diff    × diffusion_score)

# Clamped to [0.0, 1.0]
```

**Flag triggers:**

| Flag | Trigger condition | Meaning |
|------|------------------|---------|
| `vocoder_artifact` | vocoder_score > 0.6 | Strong neural vocoder signature |
| `gan_artifact` | gan_score > 0.6 | Strong GAN generator signature |
| `diffusion_artifact` | diffusion_score > 0.6 | Strong diffusion model signature |
| `uncertain` | 0.35 < final_score < 0.55 | Score is near the decision boundary |

## 4. How It Takes Input and Detects AI

### Single file

```python
from prism.sonic.tier_a import analyze_file

result = analyze_file("recording.wav")
print(result)
```

### What happens internally:

```
"recording.wav"
      │
      ▼  librosa.load(sr=22050, mono=True, duration=30)
  raw waveform [0.012, -0.034, 0.005, ...]
      │
      ▼  librosa.stft(n_fft=2048, hop_length=512)
  complex spectrogram (1025 freq bins × T time frames)
      │
      ├──▶ magnitude  (how loud each frequency at each moment)
      ├──▶ phase      (timing of each frequency)
      └──▶ mel-spec   (128 perceptual frequency bands, in dB)
      │
      ▼  classify_domain()
  "speech" / "music" / "environmental"
      │
      ├──▶ vocoder_score()   → 0.0–1.0
      ├──▶ gan_score()       → 0.0–1.0
      └──▶ diffusion_score() → 0.0–1.0
      │
      ▼  aggregate_scores()
  final_score = weighted sum → 0.73
  flags       = ["vocoder_artifact"]
  prediction  = "synthetic"   (because 0.73 ≥ threshold 0.50)
```

### Result dictionary:

```python
{
    "file_path":       "recording.wav",
    "domain":          "speech",
    "artifact_score":  0.7312,      # ← the key number. 0=real, 1=synthetic
    "vocoder_score":   0.8100,      # ← HiFi-GAN / WaveNet signature strength
    "gan_score":       0.5500,      # ← MelGAN / EnCodec signature strength
    "diffusion_score": 0.4900,      # ← AudioLDM / Stable Audio signature strength
    "sub_scores":      {"vocoder": 0.81, "gan": 0.55, "diffusion": 0.49},
    "flags":           ["vocoder_artifact"],
    "prediction":      "synthetic"  # threshold = 0.50 by default
}
```

## 5. How Accuracy is Calculated

### The concept: Ground Truth vs Prediction

The model does **not** know if it was wrong during prediction.  
Accuracy is measured **after** prediction by comparing against a labelled dataset (the "answer key").

```
┌─────────────────────────────────────────────────────────────────┐
│  File             Ground Truth    PRISM Score    Prediction      │
│  ─────────────────────────────────────────────────────────────  │
│  LA_E_100147.flac   SYNTHETIC  →    0.73    →  "synthetic"  ✅  │  True Positive
│  LA_E_100273.flac   REAL       →    0.22    →  "real"       ✅  │  True Negative
│  LA_E_100350.flac   SYNTHETIC  →    0.38    →  "real"       ❌  │  False Negative
│  LA_E_100412.flac   REAL       →    0.71    →  "synthetic"  ❌  │  False Positive
└─────────────────────────────────────────────────────────────────┘
```

### The four outcome types

```
                        PRISM Prediction
                     "synthetic"   "real"
                    ┌───────────┬──────────┐
  Ground  synthetic │    TP     │   FN     │
  Truth             ├───────────┼──────────┤
            real    │    FP     │   TN     │
                    └───────────┴──────────┘

TP (True Positive)  = AI file, correctly flagged as synthetic  ✅
TN (True Negative)  = Real file, correctly flagged as real     ✅
FP (False Positive) = Real file, wrongly flagged as synthetic  ❌ (over-alert)
FN (False Negative) = AI file, wrongly flagged as real         ❌ (missed detection)
```

### Metric formulas

```
Accuracy  = (TP + TN) / (TP + TN + FP + FN)
            → "What fraction of ALL files did we get right?"

Precision = TP / (TP + FP)
            → "When we say synthetic, how often are we right?"

Recall    = TP / (TP + FN)
            → "Of all the synthetic files, what % did we catch?"

F1 Score  = 2 × (Precision × Recall) / (Precision + Recall)
            → Balanced metric when dataset is imbalanced
```

### The threshold sweep

PRISM outputs a **continuous score** (0.0–1.0), not a binary yes/no.  
The **threshold** is the cutoff that converts score → prediction:

```
score ≥ threshold  →  "synthetic"
score <  threshold  →  "real"
```

By sweeping the threshold from 0.40 to 0.60, `run_benchmark.py` finds the optimal point:

```
Threshold  Precision  Recall    F1      Accuracy
─────────────────────────────────────────────────
  0.40       0.83      0.91    0.87      0.84    ← catches more AI but more false alarms
  0.45       0.86      0.87    0.87      0.86
  0.50       0.89      0.84    0.86      0.86    ← default
  0.55       0.91      0.79    0.85      0.86
  0.60       0.93      0.74    0.83      0.85    ← fewer false alarms but misses more AI
```

> **Lower threshold** = catches more AI (better Recall) but more false alarms (lower Precision)  
> **Higher threshold** = fewer false alarms (better Precision) but misses more AI (lower Recall)

## 10. Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Zero-shot — no ML** | Fully explainable. Works immediately on any audio without data. Not susceptible to adversarial re-training. |
| **Domain routing** | Vocoder dominates speech; GAN dominates music; diffusion dominates environmental. Weights reflect real-world generator usage patterns. |
| **LPC formants for speech** | LPC (Linear Predictive Coding) is a 50-year-old speech science technique, perfectly capturing vocal tract resonances that vocoders fail to naturalise. |
| **Phase incoherence for GAN** | GAN generators optimise the mel-spectrogram loss — they never see phase. Phase incoherence is an unavoidable mathematical consequence. |
| **30-second cap** | All artifact patterns manifest within the first 30 seconds. Capping prevents slow analysis on long files. |
| **Error isolation** | `analyze_dataset` catches per-file exceptions and marks the row as `"error"` rather than crashing the whole batch. |
| **Threshold sweep** | No single threshold fits all use cases. The sweep gives the user data to choose Precision vs Recall trade-off for their application. |

## 11. Limitations and Future Work

### Current limitations

| Limitation | Impact |
|-----------|--------|
| Heuristic thresholds are empirical | May need re-tuning for new generator families |
| Short clips (< 1 second) | Less reliable — fewer frames to analyse |
| Heavily compressed audio (low bitrate MP3) | Compression artefacts can mimic GAN checkerboard |
| Very noisy recordings | Can suppress diffusion detector signals |
| Music is harder than speech | Less distinctive formant structure |

### Roadmap — Tier B and C

```
Tier A  ✅  Zero-shot heuristics (this project)
             └─ No training data. Works now.

Tier B  ✅  Supervised classifier (Completed)
             └─ Trained SVM (RBF) on 14 Tier A features
             └─ Evaluated on 1,000 unseen test files (LibriSpeech + WaveFake)
             └─ Achieved Accuracy: 100.00%, False Positive Rate: 0.00%

Tier C  🔜  Neural embedding model
             └─ Fine-tune a pre-trained audio transformer (Wav2Vec 2.0)
             └─ Needs thousands of examples, GPU
             └─ Expected accuracy: 97–99%
```
